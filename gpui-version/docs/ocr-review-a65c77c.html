Escape handling is broken in panel mode. The command palette's primary path (Ctrl+K / activity bar) opens it via `open_command_palette` → `open_panel` (mod.rs:562), storing the palette in `active_panel` rather than a dialog. In panel mode `window.close_dialog(cx)` is a no-op (see same pattern noted in sap_import.rs:467), so closing relies on the root `on_key_down` escape handler at mod.rs:922 calling `close_panel_impl`. Because this interceptor returns `true` for `"escape"` and the caller then runs `cx.stop_propagation()`, that root handler is never reached, so Escape can no longer dismiss the palette panel. Consider mirroring the panel pattern used elsewhere (hold a `WeakEntity<SapApp>` / weak app ref and call `close_panel_impl`, or detect panel mode) so Escape closes the palette in both dialog and panel modes.
